# The Secret Language of LLMs

computers cannot directly understand words
    - convert text into numbers then passs to LLM
    - TokenID is a single token.

    # What is a token?
    - A "Token" is a unit of text defined by a tokenizer.
    - Tokenization is the process of converting text into tokens.
    - "Tokenizer" is a separate program that breaks text into tokens(encode & decode).
    - there are many tokenizer in the market.
    - each tokenizer has its own vocabulary.
    - Each LLM has its own tokenizer.
    
Words vs Characters vs Tokens

Why models use subword tokenization

`Word tokenization creates very lengthy vocabulary.
character tokenization creates very long sequences.
sub-word is a balance of both.`

"This is a boy" -> 4 tokens by using commonly used words
"Untrustable" -> 3 token "Un" + "trust" + "able"


# Vocabulary & TokenID
Every tokenizer has a vocabulary
The vocabulary is the collection of tokens that the tokenizer know how to represent directly.
"This is a boy" -> ["This", " is", " a", " boy"] -> [100, 200, 300, 400] 
"Untrustable" -> ["Un", "trust", "able"] -> [500, 600, 700]

OpenAI uses Byte Pair Encoding(BPE)
BPW builds a vocabulary by repeatedly merging frequently occuring neighbouring pieces.

Low     -> "Low"              -> [15]
Lower   -> "Low", "er"        -> [15, 35]
Lowest  -> "Low", "er", "est" -> [15, 35, 20]

# Wordpiece (Select and matach usefull patterns)
Similar to BPE, but merges pairs that maximize the likelihood of the training data.

# Unigram 
start with a larger set of possible pieces and gradually removes less useful ones.
exactly opposite to BPE


Modern tokenization usually break unfamillier text into resuable subword units rather than treating every complete word as unique.


"This is a simple sentenct in English" -> around 7 token
"KJjh kjh kjh jkghjh ghf gdf d se sdf" -> around 10-15 tokens

# Context Window
context window is the amount of tokenised information a model can process within a request or active generation context.

llm doesn't have unlimited working memory, have a limit of token that can be process at once
this is called context window
context may include
- system information
- your current/previous prompt
- uploaded document text
- retireved information
- tools output
- llm generated response
context window is shared b/w what you send and what the model generates.


# what happens when context window fills?
different application may have this differently
possible strategies:
- rejecting the request
- truncate some input
- removing older conversation
- summarising previous messages
- retrieving only previous messages
- asking the user to shorten the input
- splitting the work into multiple requests

every llm has fixed context window.

# Context Length vs Context Window
Context length is the maximum number of tokens a model can process at once.
Context window is the number of tokens that are actually processed in a request.
